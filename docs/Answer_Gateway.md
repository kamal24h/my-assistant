۳. تنظیمات فنی که واقعاً تأثیر دارند
برای پروژه فعلی شما، این موارد را به‌ترتیب اولویت اجرا کنید.
کنترل	پیشنهاد
System Prompt	فقط منابع مجاز؛ ممنوعیت دانش بیرونی و استنباط
Retrieval	فیلتر اسناد بر اساس app_id، دسترسی کاربر و دامنه مجاز
Similarity threshold	تعیین آستانه با تست واقعی پرسش‌های فارسی؛ نه انتخاب عدد دلخواه
Reranking	بررسی اینکه قطعات بازیابی‌شده واقعاً پاسخ سؤال را پوشش می‌دهند
Generation	ارسال فقط Context تأییدشده به مدل
Temperature	مقدار 0 یا نزدیک صفر برای کاهش تصادفی‌بودن؛ نه تضمین صحت
Output validation	بررسی پشتیبانی ادعاهای پاسخ از منابع پیش از ارسال
Fallback	پاسخ ثابت و کنترل‌شده در صورت نبود شواهد کافی
هشدار مهم: امتیاز شباهت بالا لزوماً به معنی وجود پاسخ در سند نیست. ممکن است سند درباره موضوع سؤال باشد، اما اطلاعات لازم برای پاسخ را نداشته باشد. بنابراین، آستانه بازیابی باید همراه با ارزیابی کفایت شواهد استفاده شود.

۵. یک نکته اختصاصی برای دستیار ERP شما
شما علاوه بر Local RAG، امکان استفاده از ERP MCP و External OpenAI API را هم دارید. بنابراین بهتر است سیاست منابع را برای هر درخواست مشخص کنید:
- پرسش درباره راهنمای فرم‌ها و فرایندها: فقط مستندات مجاز RAG.
- پرسش درباره موجودی، سفارش یا اطلاعات زنده ERP: فقط خروجی معتبر ابزار ERP MCP مجاز برای همان درخواست.
- پرسش ترکیبی: ترکیب منابع فقط در صورتی مجاز باشد که سیاست درخواست اجازه داده باشد؛ هر بخش پاسخ باید منبع خودش را داشته باشد.
- پرسش فاقد منبع مجاز: اعلام نبود اطلاعات کافی، حتی اگر مدل جواب احتمالی را از دانش عمومی خود بداند.
همچنین، ارسال پرسش به OpenAI به‌جای مدل محلی، این محدودیت را خودبه‌خود تضمین نمی‌کند؛ مدل خارجی هم باید همان Context، سیاست منابع و اعتبارسنجی را رعایت کند.
پیشنهاد نهایی من
برای پروژه شما، به‌جای تمرکز صرف بر تغییر Prompt، سه قابلیت را در اولویت قرار دهید:
1. Evidence Gate در LangGraph برای جلوگیری از پاسخ‌گویی بدون شواهد کافی.
2. Grounded Answer Validator برای بررسی تطابق ادعاهای پاسخ با قطعات مستندات.
3. Source Traceability برای ثبت doc_id، doc_name و chunk_id در meta_info.sources هر پیام دستیار.
این ترکیب احتمال پاسخ‌های ساختگی را به‌طور محسوسی کاهش می‌دهد، هرچند تضمین ریاضیِ صفرشدن خطاهای مدل نیست.
