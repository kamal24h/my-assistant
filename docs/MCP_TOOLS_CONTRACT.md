# قرارداد مورد انتظار ابزارهای ERP MCP

این فایل قرارداد پیشنهادی بین Coordinator و تیمی است که MCP Server را روی APIهای موجود ERP پیاده می‌کند. نام ابزارها نمونه‌اند و باید بعد از بررسی Swagger نهایی شوند.

## نمونه ابزار فقط‌خواندنی

```json
{
  "name": "inventory_get",
  "description": "دریافت موجودی قابل مشاهده کاربر برای یک کد کالا و انبار اختیاری",
  "inputSchema": {
    "type": "object",
    "properties": {
      "item_code": { "type": "string", "description": "کد کالا" },
      "warehouse_code": { "type": "string", "description": "کد انبار، اختیاری" }
    },
    "required": ["item_code"],
    "additionalProperties": false
  },
  "annotations": {
    "readOnlyHint": true,
    "destructiveHint": false
  }
}
```

## ابزارهای احتمالی برای بررسی با تیم ERP

- موجودی کالا بر اساس کد کالا و انبار
- وضعیت سفارش خرید/فروش با فیلترهای مجاز
- وضعیت درخواست خرید
- وضعیت تولید یا سفارش ساخت
- جزئیات فاکتور در محدوده دسترسی کاربر

این فهرست، ابزارهای پیاده‌سازی‌شده نیست؛ فقط کاندیداهایی برای نگاشت به APIهای واقعی ERP است.

## الزامات امنیتی MCP Server

1. مجوزها را در سمت سرور و برای هر فراخوانی ابزار enforce کن؛ پنهان‌کردن ابزار در `tools/list` به‌تنهایی کافی نیست.
2. tenant/user را از هویت معتبر یا token claims بگیر. به `X-ERP-User-Id` و `X-ERP-Tenant-Id` بدون اعتبارسنجی اعتماد نکن.
3. برای هر ابزار، schema دقیق و محدود تعریف کن؛ `additionalProperties: false` را در صورت امکان فعال کن.
4. در فاز چهارم فقط GET/queryهای بدون side effect را منتشر کن. ایجاد/ویرایش/حذف و عملیات دارای اثر تجاری باید ابزار جداگانه و بعد از فاز approval باشند.
5. لاگ ابزار شامل شناسه درخواست، کاربر معتبر، tenant، نام ابزار، نتیجه مجوز و زمان اجرا باشد؛ داده حساس کامل را در لاگ نریز.
6. برای خطاها جزئیات زیرساخت، SQL، token یا داده‌های متعلق به tenant دیگر را به کاربر برنگردان.
