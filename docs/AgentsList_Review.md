# بازبینی و اولویت‌بندی فهرست Agentها برای Local RAG دستیار ERP

این سند، فهرست اصلی (۴۳ مورد) را به همان ترتیب و با همان لایه‌بندی نگه می‌دارد و برای هر مورد سرنوشت نهایی، نوع پیاده‌سازی، اولویت و ارزیابی هزینه به فایده را مشخص می‌کند.

## راهنمای ستون‌ها

**سرنوشت**
- **نگه‌داری**: به‌عنوان گره مستقل در گراف می‌ماند.
- **ادغام**: در گره یا پرامپت دیگری ادغام می‌شود (ستون «یادداشت» مقصد را می‌گوید).
- **تبدیل**: از agent به تابع قطعی، ابزار یا قابلیت آماده‌ی زیرساخت تبدیل می‌شود.
- **مشروط**: فقط در صورت وجود شرط مشخص اضافه می‌شود.
- **حذف**: ارزش افزوده‌ی آن کمتر از هزینه‌اش است.

**اولویت**
- **۱**: هسته‌ی MVP، حتماً.
- **۲**: ارتقای کیفیت، بعد از MVP.
- **۳**: مشروط به نیاز واقعی.
- **۴**: agent مستقل نشود (ادغام یا حذف).

**هزینه و فایده**: بسیار کم، کم، متوسط، زیاد برای هزینه (شامل پیچیدگی و تأخیر اجرا)؛ متوسط، بالا، بسیار بالا برای فایده.

**نوع**: «LLM» یعنی فراخوانی مدل زبانی؛ «قطعی» یعنی کد معمولی بدون LLM؛ «مدل» یعنی مدل کوچک تخصصی (embedding، cross-encoder)؛ «زیرساخت» یعنی قابلیت آماده‌ی LangGraph یا ابزار بیرونی.

## مواردی که در فهرست اصلی نیست و باید اضافه شود

| مورد | اولویت | دلیل |
|---|---|---|
| Ingestion و Chunking (پارس، تکه‌بندی، متادیتا) | ۱ | کیفیت RAG بیش از هر agent به این مرحله وابسته است |
| ACL در سطح سند و chunk، و جداسازی ایندکس بین ماژول‌ها و نقش‌ها | ۱ | پیش‌نیاز ایمنی در ERP |
| متادیتای «ماژول/نسخه‌ی محصول» و ایندکس‌سازی تدریجی | ۱ | مستندات ERP با هر نسخه تغییر می‌کند |
| انتخاب و محک مدل embedding و reranker چندزبانه روی داده‌ی فارسی خودتان | ۱ | نتیجه به داده‌ی شما وابسته است |
| پردازش فارسی برای BM25 (نیم‌فاصله، ی/ک، توکن‌سازی متن ترکیبی فارسی/انگلیسی) | ۱ | کیفیت بازیابی کلیدواژه‌ای |
| دفاع در برابر prompt injection از محتوای بازیابی‌شده | ۱ | محتوای بازیابی‌شده باید «داده» باشد نه «دستور» |
| مسیر تحویل به انسان (ایجاد تیکت پشتیبانی) | ۲ | برای وقتی که سیستم نمی‌داند یا کاربر ناراضی است |
| کش پاسخ و embedding | ۲ | کاهش تأخیر روی سخت‌افزار محلی |

## معماری پیشنهادی (حدود ۸ تا ۱۰ گره)

```
Normalize
  ← Router/Intent (+ بازنویسی با تاریخچه)
  ← Hybrid Retrieve (Dense + BM25 + RRF، با فیلتر ACL)
  ← Rerank
  ← [Grade → حداکثر یک Retry]
  ← Generate (+ Citation)
  ← Output Guard (PII / قالب)
  ← Fallback / تحویل به انسان
```

- **حافظه:** checkpointer برای تاریخچه و state جلسه.
- **رصد:** tracing روی همه‌ی گره‌ها و ارزیابی آفلاین با مجموعه‌ی طلایی.
- **شاخه‌ی ابزار:** فقط از Router فعال می‌شود. ابتدا Data Lookup فقط‌خواندنی، سپس Action Executor همراه با HITL و Business Rule.

## نقشه‌ی راه پیشنهادی

1. **فاز ۱ (MVP):** ردیف‌های با اولویت ۱ + موارد جاافتاده‌ی اولویت ۱ + مجموعه‌ی طلایی ارزیابی.
2. **فاز ۲ (کیفیت):** Router/Intent، بازنویسی با تاریخچه، Grader، PII، Feedback، Data Lookup فقط‌خواندنی، فرهنگ اصطلاحات، Hallucination Checker محدود.
3. **فاز ۳ (مشروط):** بر اساس نتیجه‌ی ارزیابی فاز ۲ تصمیم بگیرید: HyDE، Compressor، Supervisor، Reasoning، حافظه‌ی بلندمدت، و در نهایت عملیات نوشتنی با HITL.
